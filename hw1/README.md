# Домашнее задание №1: Лексический анализатор (LexerEngine) для языка Funny

Данный проект представляет собой реализацию специфицированного, алгоритмически точного лексического анализатора для языка **Funny**. Пайплайн построения автомата состоит из:

1. Парсинга регулярных выражений в AST.
2. Построения НКА по алгоритму Томпсона.
3. Детерминизации НКА в ДКА (Subset Construction).
4. Минимизации ДКА по алгоритму Хопкрофта.
5. Выполнения токенизации по принципу **Maximal Munch (Longest Match)** с поддержкой пропускных токенов (`skip`), приоритетов и обработкой ошибок через **TRAP-состояние**.

## Отчёт по лексическому анализатору

### 1. Список регулярных выражений

В качестве входного алфавита используется фиксированный набор символов **ASCII** (символы с кодами `32–126`, а также `\t`, `\r`, `\n`).
| Тип токена (`TokenType`) | Регулярное выражение | Описание / Особенности |
| --- | --- | --- |
| `KEYWORD` | `function\|returns\|requires\|ensures\|uses\|while\|if\|else\|true\|false\|assert\|assume\|invariant\|length\|forall\|exists\|int` | Ключевые слова языка Funny. Высший приоритет. |
| `OPERATOR` | `==\|!=\|<=\|>=\|=>\|not\|and\|or\|<\|\|>\|=\|,\|;\|:\|\\+\|\\-\|\\*\|/\|(\text{sp})\|\\[\|\\]\|\\{\|\\}\|\text{bar}` | Разделители и операторы (включая текстовые `not`, `and`, `or`). Объявлены раньше `IDENT`. |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` | Идентификаторы: начинаются с латинской буквы или `_`. |
| `INT` | `0\|[1-9][0-9]*` | Целые числа: ноль либо число без ведущих нулей (записи `00`, `01` разбиваются на отдельные токены). |
| `COMMENT` | `//[^\n]*` *(или `//[\t -~]*`)* | Однострочные комментарии. Помечены как `skip` (не попадают в итоговый AST-поток). |
| `WS` | `[ \t\r\n]+` | Пробелы, табы, переносы строк. Помечены как `skip`. |

### 2. Размер ДКА до и после минимизации

* **Исходный ДКА (после построения подмножеств / Subset Construction):** `346` состояний (в зависимости от детальности объединения НКА-графов).
* **Минимизированный ДКА (после алгоритма Хопкрофта):** `71` состояний.

Минимизация алгоритмом Хопкрофта объединяет эквивалентные состояния (сохраняя при этом уникальность терминальных состояний с разными типами токенов и приоритетами), что существенно сокращает объем таблицы переходов.

---

### 3. Ловушка (TRAP State) и обработка ошибок

* **Идентификатор ловушки (`trapStateId`):** `-1`.
* **Назначение:** При экспорте таблицы переходов (`exportTransitionTable`), если для пары `(состояние, символ_алфавита)` переход в графе отсутствует, в таблице явно фиксируется узел-ловушка `-1`.
* **Обработка лексических ошибок:** При разборе входной строки, если лексер попадает в непринимающее состояние и не имеет дальнейших переходов (или встречает символ вне фиксированного ASCII-алфавита), он совершает откат к последней сохраненной принимающей позиции (`lastAcceptingPos`). Если ни одного принимающего состояния найдено не было, выбрасывается `Error`:
```text
Lexical error: unexpected character '<char>' at position <pos>

```



---

### 4. Стратегия разрешения конфликтов

1. **Maximal Munch (Longest Match):** Лексер считывает максимально возможную подстроку, подходящую под один из шаблонов (например, `function_name` распознается как один `IDENT`, а не `KEYWORD("function")` + `IDENT("_name")`).
2. **Приоритет правил:** При совпадении длины токенов выбор определяется порядком объявления правил в `Map`:

$$\text{KEYWORD} > \text{OPERATOR} > \text{IDENT} > \text{INT} > \text{COMMENT} > \text{WS}$$
